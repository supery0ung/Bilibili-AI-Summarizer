# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
# Run the full pipeline (Steps A → G)
python main.py run --max-items 10

# Run individual steps
python main.py fetch [--url BV1xxx BV1yyy]   # Step A: fetch + filter from Bilibili
python main.py download --max-items 5         # Step B: download audio
python main.py transcribe --max-items 5       # Step C: ASR transcription
python main.py correct --max-items 5          # Step D: LLM text correction
python main.py summarize --max-items 5        # Step E: generate summary
python main.py epub [--force-all]             # Step F: create EPUB
python main.py upload --max-items 5 [--headful]  # Step G: upload to WeChat Reading

# Bypass filters and process specific video(s)
python main.py run --url https://www.bilibili.com/video/BV1xxx
python main.py run --url BV1xxx BV1yyy

# Check pipeline status
python main.py status

# Run tests (no GPU/network needed, < 1 second)
python -m pytest tests/ -v

# Run a single test file
python -m pytest tests/test_epub.py -v

# Run a single test
python -m pytest tests/test_epub.py::test_epub_contains_summary_sections -v
```

## Architecture

The pipeline transforms Bilibili "Watch Later" videos into EPUB ebooks uploaded to WeChat Reading:

```
Step A (fetch)      → Bilibili API → rule filter → AI filter (Qwen3)
Step B (download)   → yt-dlp → audio extraction
Step C (transcribe) → Qwen3-ASR 1.7B (or Whisper) → .md transcript
Step D (correct)    → Ollama (Qwen3 8B) → .corrected.md
Step E (summarize)  → Ollama (Qwen3 8B) → .final.md (summary + corrected text)
Step F (epub)       → Pure Python zipfile → .epub
Step G (upload)     → Playwright browser automation → WeChat Reading
```

**Key design patterns:**
- Each step is a `BaseStep` subclass in `core/`. Steps are independent and resume-safe via JSON state.
- The `Pipeline` class in `core/pipeline.py` orchestrates steps and initializes clients lazily (only when needed, to conserve GPU VRAM).
- Video state transitions: `new → downloading → downloaded → transcribing → transcript_ready → correcting → corrected → summarizing → summarized → success → uploaded`
- Special states: `error` (retryable), `skipped` (AI-filtered), `skipped_old`

**State persistence** (`output/pipeline_state.json`): Each `VideoState` stores paths to all intermediate files (`audio_path`, `transcript_md`, `corrected_md`, `summary_md`, `epub_path`). The pipeline can resume from any step.

**LLM prompts** are plain `.txt` files in `prompts/` with `{title}`, `{author}`, `{text}` placeholders. Edit these to change LLM behavior without touching Python code.

## Configuration

Copy `config.example.yaml` to `config.yaml` and fill in:
- `bilibili.sessdata` / `bili_jct` / `dedeuserid` / `buvid3` — from browser cookies
- `ollama.model` — e.g., `qwen3:8b` or `qwen3.5:9b`
- `whisper.model` — if using Whisper ASR instead of Qwen3-ASR

**Video filtering rules** are in `filters.yaml`: `min_seconds`, `up_deny_contains` (UP creator blacklist), `title_deny_regex`.

**Model storage** defaults to a user cache directory. Set `BILIBILI_MODEL_CACHE` or the lower-level `HF_HOME`, `WHISPER_CACHE`, and `XDG_CACHE_HOME` env vars to use a specific drive.

## Testing

44 regression tests in `tests/` use fixtures only — no real API calls, LLM inference, or downloads. Key critical tests:
- `test_epub.py::test_epub_contains_summary_sections` — verifies EPUB includes 核心摘要, 要点列表, 完整文本 sections
- `test_step_llm.py::test_saves_summary_md_to_state` — guards against missing `summary_md` causing EPUB generation failure

Test fixtures are in `tests/conftest.py`.

## EPUB Generation

`utils/md_to_epub.py` is a pure Python Markdown→EPUB converter (no external library). The `.final.md` file must contain the summary sections generated by Step E; `utils/reset_state.py` can reset state for re-processing.
